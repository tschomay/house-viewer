Before you start

You will be moving between two dashboards, so log into both first: Namecheap (the registrar, where the records live) and Vercel (which needs to be told the domain belongs to the project). Namecheap's Advanced DNS editor is usable on a phone but cramped — if a desktop is within reach, steps 4–6 go faster there.

One thing to settle first. I looked at your Vercel account (tschomay, Hobby plan) and there is no project called roastlog-web in it. The four projects there are sound-games, auralux, tschomay-site-preview and harness-playground. So either roastlog-web lives under a different Vercel login, or it hasn't been created yet. Sort that out before step 2 — every link below assumes the project sits under the tschomay account, and you'll need to swap the account name in the URL if it doesn't.

Nothing here touches your deployment. If you stop halfway, the site keeps serving on its .vercel.app address exactly as it does now.

  1. 1 Confirm Namecheap is actually the one answering DNS

    Open the domain's Domain tab and look at the Nameservers dropdown. It must say Namecheap BasicDNS (or Premium DNS). If it says Custom DNS and lists someone else's servers, stop and tell me what it lists.

    Namecheap · Domain tab

    Why this is step 1. If the nameservers point somewhere else, the Advanced DNS tab still lets you type records and still shows a green checkmark when you save — those records are simply never served. You would do all eight steps, see nothing change, and have no error message to go on. Checking now costs ten seconds.

  2. 2 Add both domains to the Vercel project

    Vercel will not serve a domain it hasn't been told about, no matter what DNS says. Add the apex first, then the www version.

    Vercel · roastlog-web domains

    Add this one first

    roastlog.coffee

    Then this one

    www.roastlog.coffee

    When you add the apex, Vercel offers a redirect choice. Pick the plain no redirect option for both for now — you'll set the direction deliberately in step 8, once both are actually resolving.

    Red "Invalid Configuration" is expected here. It only means DNS doesn't point at Vercel yet, which is true — that's what steps 4–6 fix. Don't remove the domain and re-add it.

  3. 3 Read the apex IP Vercel is giving you

    This is the one value I can't know in advance. On that same Domains page, roastlog.coffee now shows the record it wants: an A record with an IP address. Vercel has used two over the years and hands out different ones to different projects, so read yours off the screen rather than assuming.

    It will be one of these. Tap the one that matches what Vercel shows:

    Current Vercel apex IP

    216.198.79.1

    Older Vercel apex IP — still valid

    76.76.21.21

    If Vercel shows a third address, use that one and ignore both of these. The dashboard is always right; these two are here so you don't have to retype digits on a phone keyboard.

  4. 4 Delete Namecheap's parking records

    Open Advanced DNS. Every new Namecheap domain ships with two records that will fight yours. Delete both with the trash icon at the right of each row.

    Namecheap · Advanced DNS
    • A CNAME Record with host www pointing at parkingpage.namecheap.com.
    • A URL Redirect Record with host @ pointing at http://www.roastlog.coffee/

    Leave everything else alone. If there are MX records or a TXT record starting v=spf1, those are your email — deleting them silently stops mail delivery to the domain, and it is not obvious for days. Only the two records named above should go.

    Also check for a CAA record. If one exists and doesn't list letsencrypt.org, Vercel's certificate will never issue: the domain goes green, then HTTPS hangs on "certificate is being issued" forever. Either delete the CAA record or add letsencrypt.org to it.

  5. 5 Add the A record for the apex

    Still in Advanced DNS: Add New Record → type A Record. Three fields:

    Host

    @

    Value — the IP from step 3

    216.198.79.1

    TTL

    Set it to 1 min from the dropdown, not Automatic. Automatic is 30 minutes, which is 30 minutes of staring at a stale answer every time you want to check whether a fix worked. Raise it later if you like.

    Then press the green checkmark at the end of the row. Namecheap does not save on blur — navigating away or hitting the back button discards the row with no warning. The row is saved only once the checkmark is gone and the value is plain text.

  6. 6 Add the CNAME record for www

    Add New Record → CNAME Record.

    Host

    www

    Value

    cname.vercel-dns.com

    Set TTL to 1 min, then press the green checkmark to save.

    If Vercel showed you something like 3d1f0a2b.vercel-dns-017.com instead, use that value — it's a region-specific alias and it's fine. The generic cname.vercel-dns.com above also works for every project, so either is a correct answer here.

    Host is www, not www.roastlog.coffee. Namecheap appends the domain itself. Typing the full name creates www.roastlog.coffee.roastlog.coffee, which resolves for nobody and looks completely correct in the table.

  7. 7 Check what the internet actually sees

    Give it five minutes, then run this. One copy, one paste, one return — it's read-only and safe to run as many times as you like.

    cat > /tmp/check-roastlog.sh <<'EOF'
#!/usr/bin/env bash
# Read-only. Safe to run again as often as you like.
set -u
D=roastlog.coffee

echo "== nameservers (want registrar-servers.com) =="
dig +short NS "$D"

echo
echo "== apex A (want the IP from step 3) =="
dig +short A "$D"

echo
echo "== www CNAME (want *.vercel-dns.com) =="
dig +short CNAME "www.$D"

echo
echo "== CAA (want nothing, or a line naming letsencrypt.org) =="
dig +short CAA "$D"

echo
echo "== live =="
curl -sS -o /dev/null -w 'apex -> %{http_code} %{redirect_url}\n' "https://$D" || true
curl -sS -o /dev/null -w 'www  -> %{http_code} %{redirect_url}\n' "https://www.$D" || true
EOF
bash /tmp/check-roastlog.sh

    A good result is the step-3 IP on the apex line, a vercel-dns name on the www line, and 200 on both live lines.

    On a phone with no terminal, skip this and use the propagation checker instead — then let step 8 be your confirmation.

    Check propagation worldwide

    Empty output, or the old parking IP, means wait — not that you got it wrong. Your machine and your ISP cache the previous answer for up to the old record's TTL, which on Namecheap's default is 30 minutes. Re-run before changing anything.

  8. 8 Finish in Vercel: refresh, certificate, redirect direction
    Vercel · roastlog-web domains
    • Hit Refresh next to each domain. Both should flip to Valid Configuration.
    • Vercel then issues the TLS certificate on its own. That's usually under a minute, occasionally a few. Nothing to do but reload.
    • Pick your primary. Open the Edit menu on www.roastlog.coffee and set it to redirect to roastlog.coffee — or the reverse, if you'd rather www be the real address. Both work; what matters is that one of them is canonical so you don't split analytics and SEO across two hostnames.

    You're done when both domains read Valid Configuration, and opening roastlog.coffee and www.roastlog.coffee in a browser both land on the site with a padlock, one of them via a redirect.

    If it still says Invalid Configuration after 15 minutes, Vercel is reading a different value than dig is. Almost always that's a leftover parking record from step 4 that didn't get deleted, or a row in Namecheap that was never committed with the green checkmark. Re-open Advanced DNS and count the rows — there should be exactly one A record on @ and one CNAME on www.

If something breaks later

These are the failures that show up after the page has gone green, when the cause is furthest from the symptom.

What you seeWhat it actually means
Apex loads, www gives a certificate warning The CNAME landed but Vercel never issued a cert for that hostname — usually because www.roastlog.coffee was never added as a domain in step 2. Add it and hit Refresh.
Namecheap's parking page keeps appearing The URL Redirect Record on @ is still there. A URL Redirect silently overrides the A record on the same host, so the A record looks perfect and does nothing.
Works for you, parking page for someone else Normal propagation. Their resolver still has the old answer cached. Resolves itself within the old TTL.
"Certificate is being issued" that never finishes A CAA record on the domain is blocking Let's Encrypt. See the CAA note in step 4.
Email to the domain stops arriving An MX or SPF record went missing during step 4. Namecheap keeps no history — get the values from your mail provider's setup page and re-add them.
Endless redirect loop between apex and www Both domains are set to redirect to each other in Vercel's Edit menu. Exactly one should redirect; the other serves.

Values checked against Vercel's current domain docs. The apex IP in step 5's copy block is the current default — if your dashboard shows the older 76.76.21.21, use that instead; both are live.
