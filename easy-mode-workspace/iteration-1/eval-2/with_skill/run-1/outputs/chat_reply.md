Short version: an IAM user can hold two access keys at once, and that's what makes this safe — create the second key, write it into the repo secrets, run the pipeline once and confirm the *new* key shows recent activity, then set the old key `Inactive` (not deleted) and delete it a day later. Nothing breaks in the middle because a job binds its secret values when it starts, and the old key stays valid the whole time.

One thing first, though: **these secrets aren't in a9-tracker.** This repo has no AWS in it at all — `.github/workflows/deploy.yml` deploys to Firebase Hosting and authenticates to Google over Workload Identity Federation (keyless), and its only Actions secrets are `VITE_RECAPTCHA_SITE_KEY` and `VITE_APPCHECK_DEBUG_TOKEN`. So `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` live in some other repo — tell me which and I'll point everything at it.

I put the full procedure on a page you can work through on your phone: **Rotating github-actions-deployer**. Every command is one tap to copy, it ticks off as you go, and there's a box at the top for the repo name and old key ID so nothing has to be typed twice. Two things worth knowing before you start: it needs `iam:CreateAccessKey`/`UpdateAccessKey`/`DeleteAccessKey` on that user plus repo admin on GitHub, and step 3 pipes the new secret straight from the AWS API into `gh secret set` so you never have to copy it by hand — that's where these rotations usually go wrong.
